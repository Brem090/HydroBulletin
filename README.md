# HydroBulletin — фіналізований MVP

HydroBulletin імпортує оперативні гідрологічні та метеорологічні
повідомлення, зберігає нормалізовані спостереження у SQLite, виконує
початковий контроль якості й формує службові матеріали у DOCX та PNG.

## Реалізовано

- локальне, пакетне, онлайн-, автоматичне й архівне отримання даних;
- вибір основного сервера ГЦСТ, дзеркала або автоматичного переходу
  `основний → дзеркало`;
- raw-архів із контрольними сумами та захистом від повторного імпорту;
- декодування ЗРУР52, ЗРУР53, ЗРУР71 і добових SYNOP-опадів;
- декодування групи 5 КС-15 (льодові явища) і групи 7 (товщина льоду);
- 71 гідрологічний пост трьох територій і 10 метеостанцій;
- початкові статуси якості з незмінними кодами SQLite та українськими
  підписами в інтерфейсі, консолі й розширеному Word-шаблоні;
- контрольовані ручні правки рівня й добової зміни без перезапису оригіналу;
- журнал правок з автором, причиною, часом створення та скасування;
- багаторічні максимальні, середні й мінімальні рівні у SQLite;
- оперативні вікна GUI «Панель рівнів» і «Екстремуми»;
- три регіональні Word-бюлетені за офіційними шаблонами;
- гідрологічна карта Львівської області за офіційним PNG-шаблоном;
- один хронологічний графік рівнів води за 08:00 і 20:00;
- професійно оформлений гідрограф витрат води за вибраний період;
- календарна структура результатів `Готові матеріали/рік/місяць/`;
- зв'язок кожного DOCX і PNG з використаними спостереженнями, активними
  правками та raw-файлами;
- послідовний журнал етапів і стани `Створюю…`, `Створено` або повідомлення
  про помилку в GUI;
- командний і графічний інтерфейси;
- 133 автоматизовані тести, включно з наскрізними сценаріями продуктів і
  правок, українськими підписами статусів та Windows-запускачами.

## Встановлення

Потрібен Python 3.10 або новіший.

```bash
python -m pip install -r requirements.txt
```

## Windows-запускачі

У корені залишено лише сім BAT-файлів:

| Файл | Призначення |
|---|---|
| `run_gui.bat` | Запуск основного графічного інтерфейсу |
| `run_tests.bat` | Усі автоматизовані тести |
| `run_full_demo.bat` | Один повний експлуатаційний запуск 07–09.08.2026 |
| `measure_operational_scenario.bat` | П’ять запусків і медіана часу |
| `run_typecheck.bat` | Статична перевірка Pyright |
| `build_exe.bat` | Створення Windows-збірки |
| `run_release.bat` | Запуск уже створеного EXE |

Старі окремі запускники навчальних етапів не потрібні: їхні корисні
перевірки входять до загального набору тестів або повного сценарію.

## Малий регресійний сценарій

```bash
python scripts/validate_regression.py --samples 3
```

Сценарій використовує три синтетичні TXT із `demo_data/regression`, створює
тимчасову чисту базу, три бюлетені, карту та два графіки. Він перевіряє
повторний запуск, SQLite, SHA-256 і provenance, але не є окремим
користувацьким BAT-файлом.

Повний експлуатаційний сценарій використовує рівні за 07–09.08.2026,
формує основні матеріали за 08.08.2026 і запускається через
`run_full_demo.bat`. Вимірювання п'яти незалежних
запусків на фактичному Windows-комп'ютері виконує
`measure_operational_scenario.bat`; докладний опис наведено в
`docs/VALIDATION.md`.

Повний сценарій створює окрему контрольну базу у `validation_results`, тому
не змішує перевірку з поточним робочим архівом програми.

## Графічний інтерфейс

```bash
python main.py --gui
```

У Windows також можна запустити `run_gui.bat`. У головній формі можна вибрати
дату, регіональні бюлетені, карту, обидва графіки, гідропост, період,
джерело даних, сервер ГЦСТ і кореневу папку результатів. Режим
**«Папка TXT-файлів»** дає змогу офлайн об'єднати ZRUR52, ZRUR71 і SYNOP
за вибрану дату без залежності від мережі.

У повному валідаторі рівні за 07.08 попередньо завантажуються для
міждобового QC за 08.08. Після формування матеріалів імпортується 09.08:
це дає триденний графік і контрольну неузгодженість −1/−11 см, не додаючи
майбутні дані до оперативного запуску 8 серпня.

Кнопка **Панель рівнів** показує для кожного поста:

- рівень о 08:00 за вибрану дату;
- рівень о 20:00 попередньої доби;
- добову зміну;
- статус і пояснення контролю якості українською мовою;
- ознаку активної правки.

З панелі можна змінити рівень або добову зміну. Значення вводиться у цілих
сантиметрах; причина є обов'язковою. Оригінальний запис залишається
незмінним, а нове активне значення використовують Word-бюлетені, карта,
графік рівнів і сама панель. Правку можна скасувати; її історія зберігається.

Кнопка **Екстремуми** відкриває редактор багаторічного максимального,
середнього й мінімального рівня та необов'язкових дат максимуму/мінімуму.
Початкові значення одноразово переносяться з офіційних шаблонів до SQLite,
після чого бюлетені читають їх із бази.

Під час запуску кнопка змінюється на `Створюю…`, а поле «Хід виконання»
послідовно показує перевірку параметрів, підготовку SQLite, імпорт, QC і
формування кожного вибраного матеріалу. Завершення та помилка мають окремі
чіткі стани.

## Режими командного рядка

| Режим   | Призначення                                                               |
| ------------ | ------------------------------------------------------------------------------------ |
| `local`    | Імпорт гідрологічного TXT і необов'язкового SYNOP |
| `online`   | Завантаження ЗРУР52/53/71 та SYNOP                                 |
| `archive`  | Повторна обробка raw-файла за датою й типом         |
| `auto`     | Послідовна перевірка доступних джерел              |
| `batch`    | Папка датованих ZRUR/SYNOP; у CLI задається `--batch-folder` |
| `database` | QC і формування матеріалів із наявної SQLite           |

Приклади:

```bash
python main.py --source local --file demo_data/regression/12.07.2026_ZRUR52.txt
python main.py --source archive --date 12.07.2026
python main.py --source database --date 12.07.2026 --map
python main.py --source online --date 19.07.2026 --online-types ZRUR52
python main.py --source online --gcst-source mirror --date 19.07.2026 --online-types ZRUR52
```

Параметр `--gcst-source` приймає `auto`, `primary` або `mirror`. Типове
значення `auto` послідовно перевіряє основний сервер і дзеркало.

Окреме створення графіків із SQLite:

```bash
python main.py \
  --source database \
  --date 12.07.2026 \
  --no-bulletins \
  --level-chart \
  --discharge-chart \
  --chart-station 79726 \
  --start-date 11.07.2026 \
  --end-date 12.07.2026
```

Пакетний імпорт підтримує назви `ДД.ММ.РРРР_ТИП.txt` і
`РРРР-ММ-ДД_ТИП.txt`, де тип — ЗРУР52, ЗРУР53, ЗРУР71 або SYNOP.

## Вихідні матеріали

- `Bulleten_*.docx` — регіональні бюлетені;
- `HydroMap_Lviv_ДД.ММ.РРРР.png` — карта рівня, добової зміни й температури
  води на наявних постах;
- `WaterLevel_ІНДЕКС_ПОЧАТОК_КІНЕЦЬ.png` — єдиний хронологічний ряд рівнів
  о 08:00 і 20:00;
- `Discharge_ІНДЕКС_ПОЧАТОК_КІНЕЦЬ.png` — добові витрати води.

Послідовні наявні вимірювання з'єднуються тонкою синьою лінією. Внутрішній
проміжок без спостережень показується сірим пунктиром; крайові пропуски не
підміняються штучними значеннями. Внутрішній статус `OUT_OF_RANGE`
позначається червоним, інші точки, що потребують уваги, — помаранчевим.
Активна ручна правка має статус **«Виправлено»** (`CORRECTED` у SQLite), а
продукт зберігає знімок використаного значення та ідентифікатор правки навіть
після її подальшого скасування.

Статус **«Виправлено»** належить конкретному виправленому спостереженню.
Підсумковий статус рядка в «Панелі рівнів» може залишатися **«Підозріле
значення»** або **«Дані відсутні»**, якщо інше пов'язане значення не пройшло
перевірку чи відсутнє.

Якщо для добової зміни немає рівня попередньої доби, вона має статус
**«Не перевірено»**, а не **«Підозріле значення»**. Відсутність основи для
міждобового зіставлення не вважається доказом помилки у вихідному коді.

## Онлайн-доступ

1. Скопіюйте `.env.example` як `.env`.
2. Заповніть логін і пароль.
3. За потреби змініть тайм-аут, кількість спроб і паузу між ними.

Адреси основного ГЦСТ і дзеркала вже задані у програмі. Необов'язкові
`HYDRO_SOURCE_PRIMARY_URL` та `HYDRO_SOURCE_MIRROR_URL` у `.env` дають змогу
перевизначити їх без редагування Python-коду.

`.env`, робочі бази SQLite, raw-файли й результати не додаються до
репозиторію.

## Шаблони та ресурси

- `templates/maps/HydroMap_UHMC_Lviv_template_clean.png` — шаблон карти;

## Перевірка

```bash
python run_tests.py
python run_tests.py --verbose
```

Тести охоплюють декодування, джерела, raw-архів, міграцію SQLite, SYNOP,
QC, пакетний імпорт, Word-бюлетені, карту, графіки, GUI, provenance,
контрольовані правки, екстремуми, льодові групи, індикатор `iR`, повноту
добової суми опадів та повторний запуск.

Статична перевірка типів використовує спільну для Pyright і Pylance
конфігурацію `pyrightconfig.json`:

```bash
python -m pip install -r requirements-dev.txt
python -m pyright
```

У Windows ту саму команду запускає `run_typecheck.bat`. Англомовні коди
статусів залишаються незмінними в SQLite та програмній логіці, але в
інтерфейсі, консольному підсумку й розширеному Word-шаблоні відображаються
українські назви.

Фінальний відтворюваний сценарій додатково перевіряє шість продуктів,
повторний запуск, цілісність SQLite, дублікати, SHA-256, provenance,
raw-архів і два офлайн-режими:

```bash
python scripts/validate_regression.py --samples 3
```

## Windows EXE

Збірка виконується саме на Windows:

```bat
build_exe.bat
```

Результат — `dist\HydroBulletin\HydroBulletin.exe`. Передавати потрібно всю
папку `dist\HydroBulletin`, а не лише EXE. Шаблони, карта, шрифт, мапінг і
малий синтетичний регресійний набір входять до пакета; `.env`,
`demo_data/full_private`, SQLite, raw-файли й готові матеріали не пакуються.
Робочі дані створюються поруч із EXE.

## Межі MVP

Автоматичні прогнози, таблиці запасів води, висота снігу та нові типи
продуктів не входять до MVP. Контроль якості не виправляє дані автоматично:
ручна правка завжди потребує автора й причини та не змінює первинне
вимірювання.
