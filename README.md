# HydroBulletin — тиждень 2

Другий послідовний етап дипломного інженерного проєкту з автоматизації обробки оперативних гідрологічних даних.

## Що вже працює

- локальне та онлайн-джерело зі спільним контрактом `load_text()`;
- безпечне завантаження адреси, логіна, пароля й тайм-ауту з `.env` або змінних середовища;
- отримання повідомлень ZRUR52, ZRUR53 і ZRUR71 через окремий модуль джерел;
- базова перевірка HTTP-статусу, кодування KOI8-U, порожньої відповіді, наявності кодованих записів і потрібного дня;
- незмінне збереження отриманого тексту в raw-архіві `рік/місяць/дата_тип.txt`;
- декодування ранкового рівня, добової зміни, вечірнього рівня, температури води, гідрологічних опадів і витрати води;
- часові мітки для ранкового строку та 20:00 попередньої доби;
- мінімальне походження даних: `source_type` і `source_file`;
- нормалізований SQLite-архів за моделлю «пост / параметр / час / значення / якість»;
- журнал імпортів із SHA-256 хешем і базовий захист від повторного файла та повторного вимірювання;
- безпечне доповнення вже імпортованого raw-файла новими параметрами після уточнення декодера;
- автоматичне оновлення порожньої схеми тижня 1 до схеми тижня 2;
- 53 автоматизовані тести, включно з контрольованою імітацією відповідей сайту та наскрізним сценарієм.

## Наскрізний сценарій

```text
OnlineDataSource або LocalFileSource
                ↓
      перевірка вхідного тексту
                ↓
 raw/YYYY/MM/YYYY-MM-DD_ZRURxx.txt
                ↓
             декодер
                ↓
         HydroObservation
                ↓
  нормалізовані observations у SQLite
                ↓
        консольна таблиця демо
```

## Локальна демонстрація

Не потребує мережі або службових доступів:

```bash
python main.py
```

Перший запуск створює raw-файл і записує вимірювання до SQLite. Повторний запуск показує роботу захисту від дублювання.

Лише створити або оновити схему бази:

```bash
python main.py --init-archive
```

## Онлайн-режим

1. Скопіюйте `.env.example` як `.env`.
2. Заповніть базову адресу робочого ресурсу, логін і пароль.
3. Запустіть:

```bash
python main.py --source online --date 19.07.2026
```

Типово послідовно запитуються ZRUR52, ZRUR53 і ZRUR71. Для одного типу:

```bash
python main.py --source online --date 19.07.2026 --online-types ZRUR52
```

Справжні службові доступи не потрібно й не можна додавати до репозиторію.

## Тести

```bash
python run_tests.py
```

За замовчуванням `python run_tests.py` запускає повний набір автоматизованих перевірок і показує компактний підсумок за основними групами тестів.  Для детального перегляду кожного тесту використовується команда python `run_tests.py --verbose`
Також підтримується команда `python -m unittest discover -s tests -v`.

У Windows можна використати `run_demo.bat`, `run_online_demo.bat`, `run_archive_demo.bat` і `run_tests.bat`.

## SQLite

`imports` зберігає походження кожного файла, дату бюлетеня, тип повідомлення, шлях до raw-копії та SHA-256 хеш.

`observations` зберігає окремий рядок для кожного параметра:

- `WATER_LEVEL` — ранковий або вечірній рівень, см;
- `DAILY_CHANGE` — добова зміна, см;
- `WATER_TEMPERATURE` — температура води, °C;
- `PRECIPITATION` — гідрологічні опади, мм;
- `DISCHARGE` — витрата води, м³/с.

Ця структура без дублювання логіки стане джерелом даних для бюлетенів, графіків і аналітики наступних тижнів.
