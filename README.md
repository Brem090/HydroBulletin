# HydroBulletin — тиждень 4

HydroBulletin імпортує оперативні гідрологічні та метеорологічні
повідомлення, зберігає нормалізовані спостереження у SQLite, виконує
початковий контроль якості й формує службові матеріали у DOCX та PNG.

## Реалізовано

- локальне, онлайн-, автоматичне й архівне отримання даних;
- вибір основного сервера ГЦСТ, дзеркала або автоматичного переходу
  `основний → дзеркало`;
- raw-архів із контрольними сумами та захистом від повторного імпорту;
- декодування ЗРУР52, ЗРУР53, ЗР71 і добових SYNOP-опадів;
- 71 гідрологічний пост трьох територій і 10 метеостанцій;
- початкові статуси якості `VALID`, `MISSING`, `SUSPICIOUS`,
  `OUT_OF_RANGE` та `INCONSISTENT_CHANGE`;
- три регіональні Word-бюлетені за офіційними шаблонами;
- гідрологічна карта Львівської області за офіційним PNG-шаблоном;
- один хронологічний графік рівнів води за 08:00 і 20:00;
- професійно оформлений гідрограф витрат води за вибраний період;
- розриви або пунктирні проміжки для відсутніх спостережень і ненав'язливі
  позначки QC;
- календарна структура результатів `Готові матеріали/рік/місяць/`;
- зв'язок кожного DOCX і PNG з використаними спостереженнями та raw-файлами;
- командний і графічний інтерфейси;
- 105 автоматизованих тестів, включно з перевіркою резервного сервера і повним
  сценарієм
  `архів → бюлетені → карта → графіки`.

## Встановлення

Потрібен Python 3.10 або новіший.

```bash
python -m pip install -r requirements.txt
```

## Повний демонстраційний запуск

```bash
python main.py --batch-folder demo_data/week3 --date 12.07.2026 --archive-db demo_week3.sqlite --map --level-chart --discharge-chart --chart-station 79726 --start-date 11.07.2026 --end-date 12.07.2026
```

У Windows цей сценарій запускає `run_week4_demo.bat`. Програма імпортує
демонстраційні TXT, створює три бюлетені, карту та два графіки в
`Готові матеріали/2026/Липень/`. Повторний запуск не дублює імпорти,
спостереження чи записи про продукти.

## Графічний інтерфейс

```bash
python main.py --gui
```

У Windows також можна запустити `run_gui.bat`. У формі можна вибрати:

- дату матеріалів;
- регіональні бюлетені;
- карту Львівської області;
- графік рівнів і графік витрат;
- гідропост та період графіків;
- автоматичне джерело, локальний TXT або наявний архів SQLite;
- сервер ГЦСТ: автоматично, лише основний або лише дзеркало;
- кореневу папку для результатів; підпапки року й місяця створюються
  автоматично.

Режим `Архів SQLite` дає змогу повторно сформувати матеріали без нового
імпорту. В автоматичному режимі програма спочатку звертається до основного
ГЦСТ, а за помилки або відсутності придатних кодів перевіряє дзеркало. Для
локального файла тип ЗРУР визначається за його назвою.

## Режими командного рядка

| Режим   | Призначення                                                               |
| ------------ | ------------------------------------------------------------------------------------ |
| `local`    | Імпорт гідрологічного TXT і необов'язкового SYNOP |
| `online`   | Завантаження ЗРУР52/53/71 та SYNOP                                 |
| `archive`  | Повторна обробка raw-файла за датою й типом         |
| `auto`     | Послідовна перевірка доступних джерел              |
| `database` | QC і формування матеріалів із наявної SQLite           |

Приклади:

```bash
python main.py --source local --file demo_data/week3/12.07.2026_ZRUR52.txt
python main.py --source archive --date 12.07.2026
python main.py --source database --date 12.07.2026 --map
python main.py --source online --date 19.07.2026 --online-types ZRUR52
python main.py --source online --gcst-source mirror --date 19.07.2026 --online-types ZRUR52
```

Параметр `--gcst-source` приймає `auto`, `primary` або `mirror`. Типове
значення `auto` послідовно перевіряє основний сервер і дзеркало.

Окреме створення графіків із SQLite:

```bash
python main.py \
  --source database \
  --date 12.07.2026 \
  --no-bulletins \
  --level-chart \
  --discharge-chart \
  --chart-station 79726 \
  --start-date 11.07.2026 \
  --end-date 12.07.2026
```

Пакетний імпорт підтримує назви `ДД.ММ.РРРР_ТИП.txt` і
`РРРР-ММ-ДД_ТИП.txt`, де тип — ЗРУР52, ЗРУР53, ЗРУР71 або SYNOP.

## Вихідні матеріали

- `Bulleten_*.docx` — регіональні бюлетені;
- `HydroMap_Lviv_ДД.ММ.РРРР.png` — карта рівня, добової зміни й температури
  води на наявних постах;
- `WaterLevel_ІНДЕКС_ПОЧАТОК_КІНЕЦЬ.png` — єдиний хронологічний ряд рівнів
  о 08:00 і 20:00;
- `Discharge_ІНДЕКС_ПОЧАТОК_КІНЕЦЬ.png` — добові витрати води.

Послідовні наявні вимірювання з'єднуються тонкою синьою лінією. Внутрішній
проміжок без спостережень показується тонким сірим пунктиром, а його умовне
позначення виноситься під область побудови; крайові
пропуски не підміняються штучними значеннями. Точки зі статусом
`OUT_OF_RANGE` позначаються червоним, інші точки, що потребують уваги,
помаранчевим. Початкові значення при цьому не змінюються.

## Онлайн-доступ

1. Скопіюйте `.env.example` як `.env`.
2. Заповніть логін і пароль.
3. За потреби змініть тайм-аут, кількість спроб і паузу між ними.

Адреси основного ГЦСТ і дзеркала вже задані у програмі. Необов'язкові
`HYDRO_SOURCE_PRIMARY_URL` та `HYDRO_SOURCE_MIRROR_URL` у `.env` дають змогу
перевизначити їх без редагування Python-коду.

`.env`, робочі бази SQLite, raw-файли й результати не додаються до
репозиторію.

## Шаблони та ресурси

- `templates/bulletins/` — три шаблони Word-бюлетенів;
- `templates/maps/HydroMap_UHMC_Lviv_template_clean.png` — шаблон карти;
- `resources/fonts/e-Ukraine-Regular.otf` — шрифт карти й графіків;
- `config/precipitation_mapping.json` — відповідність гідропостів
  метеостанціям.

## Перевірка

```bash
python run_tests.py
python run_tests.py --verbose
```

Тести охоплюють декодування, джерела, raw-архів, SQLite, SYNOP, контроль
якості, пакетний імпорт, Word-бюлетені, карту, графіки, GUI, provenance і
повторний запуск. Окремо перевіряється перехід на дзеркало, коли основний
сервер не повернув даних за вибрану дату.
