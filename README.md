


# HydroBulletin — тиждень 3

На третьому тижні проєкт доповнено отриманням даних із кількох джерел,
метеорологічними опадами, початковим контролем якості та формуванням трьох
регіональних Word-бюлетенів.

## Реалізовано

- повторні мережеві запити, тайм-аути та повідомлення про помилки;
- резервне отримання даних з онлайн-джерела, локального файла або raw-архіву;
- імпорт добових SYNOP-опадів за період 09:00–09:00;
- відповідність гідропостів метеостанціям у JSON-конфігурації;
- початкові статуси якості `VALID`, `MISSING`, `SUSPICIOUS`, `OUT_OF_RANGE`
  та `INCONSISTENT_CHANGE`;
- перевірка добової зміни рівня за поточною і попередньою добою;
- пакетний імпорт TXT-файлів;
- читання даних із SQLite;
- формування бюлетенів для Львівської, Івано-Франківської областей та лівих
  приток Дністра;
- зв’язок сформованого документа з використаними вимірюваннями та raw-файлом;
- мінімальний графічний інтерфейс із вибором дати, бюлетенів і джерела даних;
- коректне DPI-масштабування у Windows;
- 83 автоматизовані тести.

## Швидкий запуск

Потрібен Python 3.10 або новіший.

```bash
python -m pip install -r requirements.txt
python main.py --batch-folder demo_data/week3 --date 12.07.2026 --archive-db demo_week3.sqlite
```

У Windows цей сценарій запускає `run_week3_demo.bat`.

Демонстраційний набір містить гідрологічні дані за 11–12 липня 2026 року та
SYNOP за відповідний період. Після запуску створюються три DOCX у
`output/week3/`. Повторний запуск не дублює імпорти, вимірювання чи продукти.

## Графічний інтерфейс

```bash
python main.py --gui
```

У Windows також можна запустити `run_gui.bat`.

У формі доступні два способи отримання даних:

- `Автоматично` — програма запитує потрібні повідомлення та за потреби
  використовує raw-архів;
- `Локальний TXT-файл` — з’являються поля вибору гідрологічного файла і
  необов’язкового SYNOP.

Типи ZRUR визначаються автоматично. Для локального файла тип зчитується з його
назви, а в автоматичному режимі залежить від вибраних бюлетенів. Підпис
`Євген КОЗИРЄВ` передається до Word-шаблону без окремого поля у формі.

## Режими командного рядка

| Режим   | Призначення                                                                         |
| ------------ | ---------------------------------------------------------------------------------------------- |
| `local`    | Імпорт гідрологічного TXT і необов’язкового SYNOP          |
| `online`   | Завантаження ZRUR52/53/71 та SYNOP                                               |
| `archive`  | Повторна обробка raw-файла за датою й типом                   |
| `auto`     | Послідовна перевірка доступних джерел                        |
| `database` | Контроль якості й формування DOCX з наявних даних SQLite |

Приклади:

```bash
python main.py --source local --file demo_data/week3/12.07.2026_ZRUR52.txt
python main.py --source archive --date 12.07.2026
python main.py --source database --date 12.07.2026
python main.py --source online --date 19.07.2026 --online-types ZRUR52
```

Пакетний імпорт:

```bash
python main.py --batch-folder шлях/до/папки --date 12.07.2026
```

Підтримуються назви `ДД.ММ.РРРР_ТИП.txt` і
`РРРР-ММ-ДД_ТИП.txt`, де тип — ZRUR52, ZRUR53, ZRUR71 або SYNOP.

## Онлайн-доступ

1. Скопіюйте `.env.example` як `.env`.
2. Заповніть адресу, логін і пароль.
3. За потреби змініть тайм-аут, кількість спроб і паузу між ними.

`.env`, робочі бази SQLite та raw-файли не додаються до репозиторію.

## Word-шаблони

У `templates/bulletins/` розміщено три службові шаблони:

- `bulletin_lviv_template.docx`;
- `bulletin_if_template.docx`;
- `bulletin_left_dnister_template.docx`.

Програма заповнює дату, підпис, рівень, добову зміну, опади й температуру
води. Назви постів, небезпечні рівні та багаторічні характеристики не
змінюються. Статуси контролю якості та походження даних зберігаються у SQLite,
але не додаються як нові колонки до службового бюлетеня.

## Перевірка

```bash
python run_tests.py
python run_tests.py --verbose
```

Тести охоплюють декодування, джерела, архів, SQLite, SYNOP, контроль якості,
пакетний імпорт, Word-бюлетені, графічний інтерфейс і повторний запуск.
